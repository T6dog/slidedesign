# Design principles for decision decks

This is an original synthesis for this hub. It is not a consulting firm's internal manual. The numeric defaults in the templates are our own choices.

## Argument before layout

State the decision, audience and consequence of waiting in the brief. Build an outline in which each analytical slide makes a supported claim. Use a plain subject title for context or methodology pages when there is no finding to claim. Read the sequence of titles to find missing steps in the argument.

Slideworks' [presentation-structure article](https://slideworks.io/resources/how-mckinsey-consultants-make-presentations) describes early executive summaries, a structured analytical body, recommendations and supporting appendices. We use that general logic while keeping the slide count and order appropriate to the decision.

## The evidence determines the exhibit

For every claim, record a source, date, scope and unit before drawing a chart. Distinguish observation, assumption and forecast. Use bars to compare quantities, lines for time, and tables when exact values or qualitative distinctions matter. Show the denominator of percentages and avoid implying causality from correlation. Reconcile the numbers across slides.

Use an explicit uncertainty range when the conclusion depends on a forecast. Explain exclusions and sensitivities in the appendix. If an input is synthetic, label it on the page, not only in speaker notes.

## Visual hierarchy should carry meaning

Use a stable grid, consistent title position and one restrained accent color. Highlight the relevant series and leave comparison data neutral. Separate labels from commentary so the reader can inspect the evidence without searching around the page. Preserve useful whitespace by removing repeated explanations.

Deckary's [design guide](https://deckary.com/blog/slide-deck-design-tips) is a further reading source for hierarchy and consistency. Exact palette, type sizes, spacing and page structures in this hub are original specifications rather than copied brand standards.

## QA is part of authorship

Check the strength of the argument separately from spelling, formatting and overflow. Recalculate displayed values from the underlying data. Open the final export and inspect each page at its intended viewing size. Keep charts and tables editable where the recipient needs to update them.

[Flight Check](https://github.com/analystacademy/flight-check) provides an independently maintained review aid. Its checks and any model-generated review are inputs to human judgment, not proof of correctness.

## A useful deck ends with a decision

Name the recommendation, alternatives, trade-offs, owner and next review point. State what evidence would change the recommendation. A convincing visual identity cannot compensate for an unsupported claim.
