# Slide structures and common patterns

These original patterns use fictional data.

| Pattern | Question | Main object | Checks |
| --- | --- | --- | --- |
| Executive summary | What should we do and why? | Answer, reasons, decision request | Reasons support the answer |
| Evidence | What differs and by how much? | Native chart | Units, period, population, zero baseline for bars |
| Options | Which alternative fits? | Native table | Consistent criteria and explicit trade-offs |
| Logic | What mechanism could explain the result? | Editable diagram | Hypotheses distinguished from proof |
| Delivery plan | How will we act? | Phases, outputs, owners, gates | Dependencies and review criteria |
| Decision record | What is approved and still open? | Decision, conditions, owner, review trigger | Draft does not imply approval |

A waterfall explains an additive bridge; reconcile start, changes and end. A line chart shows time; keep intervals consistent and explain missing values. A scatterplot shows association, not automatically causation. A priority matrix needs explicit axes and a reason for each position. A heatmap needs a visible scale and scoring rule.

Place a source note close to each exhibit. Put audit detail in notes or an appendix. Avoid unreadable tables introduced only to imitate a perceived consulting aesthetic.

References for general practice: [Slideworks](https://slideworks.io/resources/how-mckinsey-consultants-make-presentations), [Deckary](https://deckary.com/blog/consulting-quality-slides), [Flight Check](https://github.com/analystacademy/flight-check). No example slide was copied.
